How this works, and what it doesn't cover yet

  • Forced-pick question: "If you had to pick one AI-driven guest-service and staffing automation platform for a hotel, Dextr or {rival}?" Asked in both name orders, 5 fresh runs each (60 answers total), via the OpenAI API (gpt-4o) directly — no browsing, no memory, no personalization.
  • Open comparison question: "Dextr vs. {rival}: which should I choose?" Asked once per order (12 answers) — this is where the reasoning notes above come from. It is not repeated, so a single odd answer could be noise.
  • The headline finding: this is a total brand-identity miss, not a competitive result. In all 12 open-comparison runs, the model describes "Dextr" as a contact-center software add-on (in one run, explicitly tied to Amazon Connect) — call routing, queuing, CRM integration, workforce management. The real Dextr, an AI front-desk and guest-service automation platform for hotels at dextr.ai, never appears once. Every forced-pick and open-comparison result below is a judgment about a different, unrelated company that happens to share a name.
  • Because the model thinks "Dextr" is a generic contact-center tool, it loses most forced-pick runs outright: 0 of 10 against Canary Technologies, 1 of 10 against ALICE (Actabl), 2 of 10 against Volara/Akia/Operto, 3 of 10 against Duve. That's the opposite pattern from this suite's other knowledge-gap cases (Clera, Runway's weaker rivals), where the unfamiliar name won by default — here the hospitality-specific rivals win by default instead, because the model's "Dextr" sounds generically applicable to anything, not specifically built for hotels.
  • Not yet covered: pricing, integrations, onboarding, setup and support as separate scored dimensions — with the brand itself unrecognized, there's no real comparative fact sheet to build here. Also not covered: any engine besides this one, and any run with browsing or a logged-in session.
